# 外接摄像头拍摄端规格草案

创建日期: 2026-06-24  
适用项目: `mistakeNote` 孩子错题知识库  
阶段定位: 采集入口 MVP，不是完整 Web 错题系统

---

## 1. 目标

做一个 Mac 本地拍照小工具，用外接 USB 摄像头直接拍完整试卷照片，保存到本地错题素材目录，为后续“AI 返回疑似错题框 → 家长确认 → 自动裁出错题图”做输入。

这一步只解决一件事:

> 把“手机拍照再传到 Mac”改成“Mac 上打开拍照 UI，直接保存到错题仓库”。

第一版不追求自动识别错题、不自动归档到具体错题文件夹、不自动生成讲解。先把采集入口做稳定。

---

## 2. 已验证事实

2026-06-24 已在本机验证:

- macOS 能识别外接摄像头: `USB Camera`
- AVFoundation / ffmpeg 能枚举到设备:
  - `[0] USB Camera`
  - `[1] jack’s iPhone Desk View Camera`
  - `[2] jack’s iPhone Camera`
- 已成功用 `[0] USB Camera` 抓取一帧 JPEG
- 测试图片分辨率: `1920x1080`
- 测试输出: `/tmp/codex-usb-camera-test.jpg`

当前风险:

- 测试图明显过曝，说明后续 UI 不能只做“能拍”，还要做实时预览和最基本的画面质量提示。

---

## 3. 用户流程

推荐流程:

```text
启动本地拍照程序
        ↓
浏览器打开拍照 UI
        ↓
自动选择或手动选择 USB Camera
        ↓
实时预览摄像头画面
        ↓
把试卷放进 A4 辅助框
        ↓
点击“拍照”
        ↓
保存原始照片到 inbox
        ↓
显示最近拍摄缩略图
        ↓
后续进入错题识别/人工确认流程
```

第一版必须保留“人眼确认照片质量”这一步。试卷拍歪、过曝、阴影严重时，应该立刻重拍，不要把垃圾图片丢给后面的 AI。

---

## 4. 拍照端功能范围

### 4.1 MVP 必做

1. **启动本地服务**
   - 一个命令启动，例如 `npm run camera` 或 `python ...`。
   - 自动打开本地页面，例如 `http://localhost:8731`。

2. **摄像头选择**
   - 默认优先选择 `USB Camera`。
   - 如果没有匹配到外接摄像头，显示可选摄像头列表。
   - 不默认选择 iPhone Continuity Camera，避免误用。

3. **实时预览**
   - 页面中央显示摄像头实时画面。
   - 预览比例固定为 16:9，因为当前 USB Camera 输出是 `1920x1080`。

4. **A4 对齐辅助框**
   - 在预览上叠加半透明 A4 边框。
   - 提示试卷四角尽量落在框内。
   - 第一版只做视觉辅助，不强制自动裁纸。

5. **拍照保存**
   - 点击“拍照”后保存当前帧。
   - 同时保存:
     - 原始照片
     - 一份元数据 JSON
   - 拍摄成功后显示缩略图和文件路径。

6. **最近拍摄列表**
   - 显示本次会话最近 10 张。
   - 每张显示:
     - 缩略图
     - 拍摄时间
     - 文件名
     - “打开文件夹”或“复制路径”

7. **最小画质提示**
   - 第一版至少提示:
     - 画面过曝
     - 画面过暗
   - 不做复杂图像评分。

### 4.2 第一版暂不做

- 不做错题自动识别
- 不做自动切题
- 不做 OCR
- 不做知识点识别
- 不做自动生成 `note.md`
- 不做数据库
- 不做账号、云同步、多用户
- 不做完整错题浏览器项目

这些后面可以接，但不能混进拍照 MVP。

## 5. 代码放置位置

建议新增:

```text
mistakeNote/
  tools/
    camera-capture/
      README.md
      package.json
      src/
        server.js
        public/
          index.html
          app.js
          styles.css
```

理由:

- `tools/` 表示这是本地工具，不是孩子错题内容本身。
- `camera-capture/` 单独隔离，未来可删除、重写或换技术栈，不污染错题档案。
- 不放进 `二年级/数学/`，因为拍照工具未来会服务所有年级和科目。
- 不放进 `_system/`，因为 `_system/` 现在更像模板和测试区，不适合放运行程序。

第一版技术选型建议:

- Node.js 小服务 + 浏览器 UI。
- 浏览器端用 `navigator.mediaDevices.getUserMedia()` 做实时预览。
- 点击拍照后把 canvas 图片 POST 到本地 Node 服务保存。

不建议第一版做原生 macOS App。原生 App 权限、打包、签名成本高，不符合现在“先打通采集入口”的目标。

## 6. 文件存储分类

建议新增一个统一素材入口:

```text
mistakeNote/
  _inbox/
    scans/
      2026-06-24/
        20260624-210501-usb-camera-001.jpg
        20260624-210501-usb-camera-001.json
```

### 6.1 为什么放 `_inbox/scans/`

- `_inbox` 表示“还没归档、待处理素材”。
- `scans` 表示整张试卷照片，不是单道错题图。
- 按日期分目录，避免几百张图堆在一起。
- 这个目录服务所有年级/科目，不提前假设这张照片一定是“二年级数学”。

### 6.2 文件命名

建议格式:

```text
YYYYMMDD-HHMMSS-usb-camera-NNN.jpg
YYYYMMDD-HHMMSS-usb-camera-NNN.json
```

例子:

```text
20260624-210501-usb-camera-001.jpg
20260624-210501-usb-camera-001.json
```

命名原则:

- 时间戳保证排序。
- `usb-camera` 表明来源。
- `NNN` 用于同一秒多拍或连拍。
- 不在文件名里写科目、题型、孩子状态；这些应该在后续归档时确认。

### 6.3 元数据 JSON

每张原始照片旁边保存同名 JSON:

```json
{
  "captured_at": "2026-06-24T21:05:01+08:00",
  "source": "usb-camera",
  "device_label": "USB Camera",
  "width": 1920,
  "height": 1080,
  "stage": "raw_scan",
  "status": "unprocessed",
  "notes": ""
}
```

后续识别错题时可以追加:

```json
{
  "status": "detected",
  "detected_regions": [
    {
      "id": "r1",
      "type": "suspected_wrong_question",
      "box": { "x": 120, "y": 300, "width": 640, "height": 420 },
      "confidence": 0.82,
      "reason": "red_cross_near_question"
    }
  ]
}
```

但第一版拍照工具只负责写基础元数据。

## 7. 后续归档流向

原始照片进入 `_inbox/scans/YYYY-MM-DD/` 后，不立刻移动到具体错题目录。

后续处理流程:

```text
_inbox/scans/YYYY-MM-DD/整张试卷.jpg
        ↓
AI/图像处理找疑似错题框
        ↓
家长确认错题区域
        ↓
导出单题截图
        ↓
新建或补充:
二年级/数学/错题/YYYY-MM-DD-题目简称/原题.png
```

归档时才决定:

- 年级
- 科目
- 来源
- 题目简称
- 错因
- 是否需要互动版

这符合当前项目原则: 文件是真相，但不要过早自动化 schema。

## 9. 验收标准

MVP 完成必须满足:

1. 能枚举本机摄像头，并优先选中 `USB Camera`。
2. 页面能看到实时预览。
3. 点击一次“拍照”，能保存一张 JPEG 到 `_inbox/scans/YYYY-MM-DD/`。
4. 保存的 JPEG 分辨率不低于摄像头原始预览分辨率。
5. 同目录生成同名 `.json` 元数据。
6. 页面显示最近拍摄缩略图。
7. 断开 USB Camera 时，页面给出明确错误，不静默失败。
8. 过曝/过暗时有基础提示。

最低验证命令:

```bash
find _inbox/scans -type f | sort
sips -g pixelWidth -g pixelHeight _inbox/scans/YYYY-MM-DD/*.jpg
```

人工验收:

- 拍一张真实试卷。
- 肉眼检查题目文字是否可读。
- 肉眼检查红笔批改痕迹是否可见。
- 如果不满足，先调整拍摄工位，而不是先调 AI。

---

## 10. 最可能翻车的点

1. **过曝**
   - 已在测试抓帧中出现。
   - 解决优先级高于 AI 识别。

2. **摄像头不是俯拍固定**
   - 手持或斜拍会导致后续裁切不稳定。
   - 最好做一个固定支架，让试卷每次位置接近。

3. **1080p 对 A4 文字可能不够**
   - 如果整张 A4 文字太小，后续 OCR/AI 识别会受影响。
   - MVP 先实测；如果不够，再考虑 4K 摄像头或分区拍摄。

4. **自动识别过早介入**
   - 第一版只做采集。
   - 先保证照片质量和文件流，再接错题框识别。

---

## 11. 推荐实施顺序

1. 搭 `tools/camera-capture/` 最小本地服务。
2. 做摄像头实时预览和选择。
3. 做拍照保存到 `_inbox/scans/YYYY-MM-DD/`。
4. 做最近拍摄列表。
5. 加基础过曝/过暗检测。
6. 用 3 张真实试卷测试:
   - 普通白纸试卷
   - 有红叉/圈画的试卷
   - 光线不理想的试卷
7. 确认照片质量稳定后，再设计“AI 疑似错题框”下一阶段。

---

## 12. 当前决策建议

建议现在批准的范围:

- 做本地 Web 拍照工具。
- 代码放 `tools/camera-capture/`。
- 原始照片放 `_inbox/scans/YYYY-MM-DD/`。
- 第一版只做拍照、保存、预览、基础画质提示。

暂不批准的范围:

- 自动识别错题。
- 自动归档错题。
- 自动生成讲解。
- 完整错题 Web 系统。

这不是保守，是避免把“采集入口”做成一个没验证过的全流程系统。先把照片稳定拿到手，后面的 AI 才有意义。
