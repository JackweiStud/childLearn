# mistakeNote · 孩子错题知识库

> 这是 `childLearn/` 项目下的"错题"模块。本文说明它为什么存在、要解决什么、长什么样。所有结构决策、技术选型都应该回到本文校准。

---

## 一、原始诉求

每天会反复遇到的场景:

- 孩子做完作业,有几道错题
- 我拍照存到手机相册里
- 想给他讲,有时候讲一两个小时他还是不懂
- 然后照片堆在相册里,过段时间忘了哪些是错的
- 期末复习时翻不动几百张照片,只能凭印象拣题

这背后有四个底层问题:

1. **错题没沉淀** —— 拍了照,但没结构化保存,过段时间就找不到
2. **讲题不高效** —— 传统讲解方式对视觉/动作型孩子无效,经常讲到自己崩溃
3. **复习无依据** —— 临考时不知道孩子真正弱的是哪类题,只能题海战术
4. **没有举一反三** —— 一道错题对应的同类变体题,得自己去找,效率低

---

## 二、价值

这件事做成的价值是**分层**的——做之前先想清楚每一层为谁服务。

### 对孩子

- 真正理解每一道错题(而不是死记答案)
- 复习面对的不是题海,是他**自己曾经栽过的**、有针对性的题
- 看见自己的进步——这道当时不会的题,现在会了
- 慢慢学会"我不会什么"这种元认知,比成绩重要十倍

### 对家长

- 不再 3 小时讲一道题—— AI 帮做互动教学,孩子点几下就懂
- 看见孩子的"弱点地图"——哪类题反复栽、哪类已掌握,数据说话
- 期末复习有依据——按"还没掌握 + 知识点权重"挑题,而不是凭感觉
- 减少情绪损耗——讲不通时调用工具,不用反复硬讲伤亲子关系

### 对长期(2–5 年)

- 沉淀出一份属于**这个孩子**的"学习档案"——他怎么思考、哪些坎容易栽、什么方法对他管用
- 这份方法论可以横向复制——三年级数学、二年级英语都能套
- 是种"教育资产"——以后回看,比成绩单更有意义,也是这个家庭独有的方法学

## 三、核心设计点

按重要性排序:

### 1. 文件是真相 (local-first)

数据全部以 markdown + 图片躺在本地文件夹,Git 版本管理。任何工具(Obsidian、未来的 web 项目、Claude)都只是这份数据的"视图",数据不锁死在任何工具里。哪天换工具,数据原封不动。

### 2. 静态档案 + 动态视图

- **静态档案** = 这个文件夹本身,跟着孩子长大
- **动态视图** = Obsidian(关系图)、未来的 web 项目(看板/筛选)、Claude(诊断/教学/出题)

视图可以换、可以重写,档案不动。

### 3. 两区结构:孩子区 / 家长区

每道错题笔记分两部分。**孩子模式**只看题面和自己的错法,看不到正解(不然这本就废了)。**家长模式**全部展开。

### 4. 互动教学优先于文字讲解

能用动起来的形式讲清楚的,就不用静态图。能让孩子自己点出来的,就不要替他想。Claude 出的互动版(.jsx / .html)跟错题绑定存在同一文件夹。

### 5. 复测节奏内置

每道题不是"讲过 = 学会"。**当天会、隔三天还会、隔一周还会**——才算真掌握。复测记录是错题的核心元数据,不是附属信息。

### 6. 知识点反向链接

每道错题挂到一个或多个"知识点"概念上(`[[和差问题]]`)。Obsidian 关系图能直接看到:某个概念下挂着几道错题、哪些已掌握、哪些还在反复栽。这是这套系统最有长期价值的东西。

### 7. 多年级多科目对称

目录结构 `年级 / 科目 / ...` 整齐对称。今天二年级数学打样,明天可以原样复制到二年级英语、三年级数学。

### 8. 不要过早自动化

先用"手动 + Claude 对话"跑通工作流,沉淀几十道真实错题之后,再考虑写 web 项目自动化。**先验证,再投资**。过早自动化会让 schema 边写边改,前端推倒重来,典型陷阱。

## 四、孩子怎么使用(现在 → 未来)

整套系统的设计要从"现在 100% 家长主控"**逐步过渡**到"未来他自己掌控"。这才是教育的真正目的。

### 现阶段(二年级,7–8 岁)

- **家长主控全部**:拍照、上传、跟 Claude 沟通、归档
- 孩子的入口只有两个:
  - **做互动教学**(像邮票题那个,他爱玩)
  - **重做错题**(我打开孩子模式,他重做一遍)
- 他不接触 Obsidian、不接触 web 项目、不接触 Claude 对话

### 家长日常使用三步

这不是全自动归档系统。现阶段正确方式是"工具采集 + Claude/Codex 半自动归档 + 家长确认错点"。

#### 第一步:拍照 / 截图

纸质作业或试卷用拍照台:

```bash
cd /Users/jackwl/Code/childLearn
bash mistakeNote/拍照.sh
```

浏览器打开后拍整页,或用区域截图工具框出单题。文件会进入:

```text
mistakeNote/_inbox/scans/YYYY-MM-DD/
```

如果素材已经来自微信、相册或系统截图,也可以直接保存到本地,后续放进 `temp/`。

#### 第二步:生成干净 PDF

如果原图清楚、没有涂写遮挡,这一步可以跳过。

如果原题有学生答案、批改、圈画或倾斜,用 `rebuild-clean-exam` 走干净试卷重建流程。注意:干净 PDF 不是简单擦图,而是 AI/人工确认题目事实后用 ReportLab 矢量重建;非 AI 彩色擦除实验已回退,不要把它当默认方案。

输出默认在:

```text
tools/rebuild-clean-exam/outPdfFile/
```

#### 第三步:归档错题

把第一步的原题图、第二步生成的干净题 PDF(如果有)、孩子草稿图(如果有)放进:

```text
/Users/jackwl/Code/childLearn/mistakeNote/二年级/数学/temp/
```

然后在 Claude/Codex 里说:

```text
/新错题 题目简称
```

归档命令会按闸门继续:先列素材让家长确认,再强制询问孩子真实错点,最后生成 `<题目简称>.md`、`<题目简称>·变形.md` 和 `打开.html`(文件名 = 题目简称,见 `CLAUDE.md` 命名约定)。孩子真实错点必须由家长口述,不能让模型猜。

### 1–2 年后(三、四年级)

- 他能自己打开 web 项目的"孩子模式"
- 自己浏览错题列表(只看题面,看不到答案)
- 点"重做",填答案,系统自动判分
- 答对自动标记"已掌握",答错触发家长介入
- 他第一次有"**我有自己的错题库**"这个意识

### 3–5 年后(五六年级 / 初中)

- 他直接对接 Claude:拍完照自己上传,自己听讲解
- 自己维护错题状态、安排复习节奏
- 家长从"主控"退到"监督"——看看 dashboard,他卡住了再介入
- 他学会的不只是某道题,而是**"如何自己学习"**

### 成功标准

整个系统的真正成功标志不是错题攒了多少,而是——

> 他什么时候开始**嫌我多管闲事、自己开始用这套工具**。

那一天就是这个项目的毕业典礼。

## 五、范围边界(明确不做什么)

- ✗ **不做 AI 替孩子答题** —— 这不是答案生成器,是理解辅助
- ✗ **不做家长群分享** —— 这是私人档案,不社交,不公开
- ✗ **不做云同步 / SaaS** —— 本地文件 + Git 就够,不增加复杂度
- ✗ **不做多用户 / 协作** —— 一个孩子一份档案,专注
- ✗ **不做应试技巧 / 奥数题库** —— 只装"卡了的题",不堆资料
- ✗ **不做成绩跟踪 / 排名** —— 不让数据焦虑反过来伤孩子

## 六、第一阶段(Phase 0)目标

- 建好目录骨架和两个模板(错题模板、知识点模板)
- 用现有的"邮票一样多"题走通归档流程,作为样板
- 起 Git 仓库(私有)
- Obsidian 打开能看到基本的关系图雏形

### 完成标志

> 当下一道错题来了,你能在 5 分钟内向自己说清楚:"它应该放哪个文件夹、文件叫什么、frontmatter 怎么填、要不要做互动版。"

不能,就说明结构还没设计对,继续调。

## 七、本文档的角色

这份 README 是整个 mistakeNote 项目的"北极星"。

- 任何技术决策模糊时,回到这里校准:**这件事是不是支持上述价值?**
- 任何"要不要加这个功能"的犹豫,看第五节"不做什么"
- 半年后忘了为什么要这么设计,从头再读一遍

**修改本文档需要慎重**,因为它定义了系统存在的意义。其他文件(schema、模板、代码)都可以随时改。
